# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
yarn dev          # Start dev server on port 3030
yarn build        # Type-check + Vite build
yarn lint         # ESLint
yarn typecheck    # TypeScript check without emit
yarn generate-gql # Regenerate GraphQL types from schema (requires backend running)
yarn preview      # Preview production build
```

No test runner is configured in this project.

## Environment Variables

Copy `.env` and adjust as needed. Required variables:
- `VITE_API_BASE_URL` — GraphQL HTTP endpoint (default: `http://localhost:5050/graphql`)
- `VITE_WS_BASE_URL` — GraphQL WebSocket endpoint (default: `ws://localhost:5050/graphql`)
- `VITE_DEV_TOOLS_ENABLED` — set to `"true"` to enable TanStack Router devtools

## Architecture

### Feature-Sliced Design (FSD)

The codebase enforces strict FSD layering via `eslint-plugin-boundaries` (`eslint.boundaries.js`). Import direction is one-way top-down:

```
app → pages → widgets → features → entities → shared
```

Each slice (`features/*`, `entities/*`, `widgets/*`) must be imported **only through its public API** (`index.ts` / `index.tsx`). Direct internal imports are disallowed by ESLint.

### Routing

TanStack Router with file-based routing. Route files live in `src/pages/` and are auto-discovered by the Vite plugin. The generated route tree is written to `src/shared/router/routerTree.gen.ts` — **do not edit this file manually**.

Route segments prefixed with `_` are pathless layout routes (e.g. `_inner` wraps authenticated pages, `_auth-form` wraps auth pages). Guards run in `beforeLoad` hooks.

Role-based routes: `/teacher/*`, `/student/*`, `/admin/*` — each under `src/pages/_inner/`.

Navigation constants are centralized in `src/shared/navigation.ts`.

### GraphQL / Apollo Client

- Apollo Client v4 with `InMemoryCache` — configured in `src/shared/clients/graphql/`
- Auth tokens (JWT) stored in `localStorage` via `src/shared/model/tokens/index.ts`; token refresh is handled manually with a raw `fetch` call before Apollo re-sends the request
- GraphQL codegen outputs typed helpers to `src/shared/api/` — run `yarn generate-gql` after adding/modifying `.graphql.ts`, `.query.ts`, or `.mutation.ts` files
- Use the `graphql()` function from `@/shared/api` to tag query/mutation strings for type inference

### Auth Flow

- `authorizedGuard` / `unauthorizedGuard` in `src/shared/guards/` redirect based on presence of `accessToken` in localStorage
- The `/_inner` route group uses `authorizedGuard` in `beforeLoad` to protect all inner pages

### UI

- Tailwind CSS v4 (via `@tailwindcss/vite` plugin)
- Radix UI primitives wrapped in `src/shared/ui/kit/`
- SVG files imported as React components via `vite-plugin-svgr` (named exports)
- `next-themes` for dark/light mode; theme context in `src/shared/model/theme/`
- Do **not** use `FC` / `React.FC` / `FunctionComponent` type annotations — banned by ESLint

### Naming Conventions (enforced by ESLint)

- Exported `const` variables: `camelCase`, `PascalCase`, or `UPPER_CASE`
- Props interfaces: `PascalCase` ending in `Props`, no `I` prefix (e.g. `ButtonProps`, not `IButtonProps`)
- Use `import type` for type-only imports (`@typescript-eslint/consistent-type-imports`)
- Import order enforced: types → builtins → externals/internals → parent/sibling → index → object, with newlines between groups
